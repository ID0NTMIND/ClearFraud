# ClearFraud: Explainable Fraud Detection Service
**Проект:** Сервис по обнаружению мошеннических транзакций с генерацией объяснений на базе LLM.
**Модуль:** My First Data Project (MFDP)
**Автор:** Смалев Дмитрий

---

## 1. Бизнес-анализ (Business Understanding)

### 1.1 Организационная структура и пользователи
*   **Заказчик:** Банковский сектор или финтех-компания (например, служба финансового мониторинга).
*   **Основной пользователь:** Фрод-аналитик (сотрудник службы безопасности банка), который принимает финальные решения по блокировке карт.
*   **Контакт:** обратная связь осуществляется через менторов и экспертов курса.

### 1.2 Бизнес-цель проекта
*   **Главная цель:** Снижение финансовых потерь банка от мошеннических транзакций при одновременном сохранении лояльности клиентов (минимизация ложных блокировок).
*   **Вторичная цель (Продуктовая):** Сокращение времени разбора одного фрод-алерта (Time-to-Resolution) за счет автоматической генерации понятных объяснений от LLM.

### 1.3 Существующие решения и их недостатки
*   **Правила (Rule-based):** Простые пороги (например, "блокировать всё > 100 000 руб."). *Минус:* много ложных срабатываний, мошенники легко обходят.
*   **Классический ML (Черный ящик):** Модели (XGBoost, нейросети) ловят сложные паттерны, но выдают только вероятность (например, 0.87). *Минус:* аналитик не понимает причину, тратит 5-10 минут на ручной разбор каждого алерта, что дорого и медленно.

## 1.1 Текущая ситуация (Assessing current solution)

### 1.1.1 Ресурсы
*   **Железо:** Имеется персональный ноутбук (CPU). Для обучения моделей достаточно мощности локального процессора. Для генерации текстов используется бесплатный API Google Gemini (не требует локальных GPU).
*   **Данные:** Используется открытый датасет **"Credit Card Fraud Detection Dataset 2026"** (Kaggle)
(https://www.kaggle.com/datasets/mohankrishnathalla/credit-card-fraud-detection-dataset-2026) (Синтетический). Он содержит 100 000 транзакций с интерпретируемыми признаками (категория мерчанта, расстояние от дома, тип устройства) и реалистичным дисбалансом классов (~2%).
*   **Эксперты:** Консультации с менторами AI Talent Hub.

### 1.1.2 Риски проекта и план их минимизации
| Риск | Вероятность | План минимизации |
| :--- | :--- | :--- |
| **Не уложиться в сроки** | Средняя | Работа строго по методологии CRISP-DM. Фокус на создании MVP (бинарная классификация + простой Streamlit интерфейс). |
| **Плохое качество данных (синтетика)** | Высокая | Использование современного датасета 2026 года, который откалиброван по реальным исследованиям ФРС и FICO. Честное обоснование выбора на защите. |

## 1.2 Решаемые задачи с точки зрения аналитики (Data Mining goals)

### 1.2.1 Метрики оценки
Поскольку в данных экстремальный дисбаланс классов (мошенников ~2%), стандартная метрика Accuracy не подходит (она будет 98% даже у модели, которая вообще не ловит фрод).
*   **Основная ML-метрика:** **PR-AUC** (Precision-Recall AUC). Она фокусируется на меньшинстве (мошенниках) и чувствительна к ложным срабатываниям.
*   **Дополнительные метрики:** **F1-score** (баланс точности и полноты) и **Recall** (доля пойманных мошенников).
*   **Метрика для LLM:** **Faithfulness** (достоверность) — проверка, что сгенерированный текст строго соответствует входным SHAP-значениям.

### 1.2.2 Критерии успешности
*   **ML-критерий:** Достижение PR-AUC > 0.75 и F1-score > 0.70 на тестовой выборке.
*   **Бизнес-критерий:** Сокращение времени разбора алерта (симуляция) с 5 минут до 1 минуты за счет готового объяснения от LLM.
*   **Продуктовый критерий:** Снижение доли ложных срабатываний (False Positive Rate) относительно базового правила "блокировать всё > X".

## 1.3 План проекта (Project Plan)

Проект реализуется в 6 этапов (CRISP-DM):
1.  **Бизнес-анализ (Текущий этап):** Определение целей, метрик и рисков.
2.  **Анализ данных (Data Understanding):** EDA, проверка распределений, корреляционный анализ признаков (например, `distance_from_home_km` и `is_fraud`).
3.  **Подготовка данных (Data Preparation):** Обработка пропусков, One-Hot Encoding для категориальных признаков, масштабирование числовых признаков (RobustScaler), разбиение на Train/Val/Test.
4.  **Моделирование (Modeling):** Обучение Baseline (Logistic Regression) и основной модели (XGBoost/CatBoost). Подбор гиперпараметров.
5.  **Оценка результата (Evaluation):** Расчет метрик, интерпретация модели через **SHAP** (выделение топ-5 признаков), генерация объяснений через **Gemini API**.
6.  **Внедрение (Deployment):** Разработка API (FastAPI) для приема транзакций и веб-интерфейса (Streamlit) для визуализации работы сервиса.
